# 单车路径规划 RL 训练建议

> 基于你和 Gemini 的讨论，补充一些我的思考。

---

## 算法选择

**推荐顺序：PPO → SAC → TD3**

理由：
- **PPO**：稳定、文档多、SB3 内置。适合先跑通流程，验证整个 pipeline 是否work。
- **SAC**：样本利用率高，探索能力强。如果你发现 PPO 在复杂弯道总是撞车，换 SAC。
- **TD3**：可以作为对比实验，看哪个最终到达率高。

**不推荐 DQN**：离散动作不适合方向盘连续控制。

---

## 训练策略建议

### 1. 先做小规模验证
不要一上来就跑 10 万步。先用 5000-10000 步验证：
- 环境是否正常 reset/step
- 奖励是否有反馈（每步 reward 不是 0）
- 模型输出是否在合理范围

### 2. 奖励函数设计（关键）
不要只靠 `arrive_dest`。加上 shaping reward：
```python
reward = +1.0 if close_to_dest    # 靠近终点
         -10.0 if crash          # 撞车
         -0.1 if off_route       # 出界
         +speed * 0.01           # 保持运动
```
这样模型才能"知道"怎么走，而不是随机撞运气。

### 3. 保存检查点
每 5000 步保存一次，训练崩了可以从中间恢复。

## 数据采集 vs 在线训练

你的两个选择：

| 方案 | 说明 | 适合场景 |
|------|------|----------|
| **在线训练（推荐）** | SB3 直接在环境里训练，不单独采集数据 | 比赛时间紧，单车场景够用 |
| **模仿学习（离线）** | 先手动采集轨迹，再训练 | 有大量人类演示数据 |

**建议**：比赛用在线 PPO 训练，不单独采集数据。MetaDrive 本身就是在线训练友好。

## 代码结构建议

```
workspace/
├── train_ppo.py        # 训练脚本
├── test_model.py        # 测试脚本
├── reward_function.py # 奖励函数（单独写，方便调）
└── requirements.txt     # 依赖列表
```

**不要**把所有代码写在一个脚本里。训练、测试、奖励函数分开，调试效率高。

---

## 时间分配建议

按你的复赛计划：
- 环境搭建：1-2天（快完成了）
- 数据采集/训练：**5-7天**（最花时间）
- 适配提交：2-3天

**重点**：训练阶段预留足够时间，不要最后几天才开始。PPO 训练 10 万步在 Kaggle T4 上约 1-2 小时，预估时间做好。

## 我的建议

1. **先跑通 PPO**，不要在算法选择上纠结太久
2. **先小地图**（seed 固定，2-3 个路段），等收敛再加难度
3. **每改一个参数**记录结果，方便对比
4. **本地验证脚本能跑**，再去 Kaggle 上长时间训练
